# voice-control · 语音客服

给 **Claude Code 这类 agent 装上耳朵和嘴**，顺便给了一套能跑的**语音客服**示例。

- 🎤 **耳朵**：你对着麦克风说话 → 转成文字喂给 agent
- 🔊 **嘴**：agent 的话 → 合成语音 → 念给你听
- 🏢 **换壳**：同一套代码，换个 json 就是另一个行业的客服（附诊所 / 餐馆两个例子）
- 🌐 **网页版**：浏览器按住说话，手机也能开

> 这是给中文 Windows 环境写的，踩过的坑都记在下面 —— **那部分可能比代码本身值钱。**

---

## 这能干什么

**对讲机模式**（能做的）：

```
你说一句 → agent 听见 → 它回一句 → 你听见
```

**不是电话模式**（做不到的）：

```
一直听着、随时打断、像真人通话
```

原因很实在：**agent 是"跑命令"的模式**——命令跑完这一轮就结束了，没法后台一直挂着耳朵。
想要电话那种，得有一个常驻服务，那是另一套东西。

```

$env:DEEPSEEK_API_KEY    = "sk-你的deepseek密钥"
```

```python
# 办法二：复制 config.example.py 改名成 config.py，填进去
```

> ⚠️ **`config.py` 不要传上 GitHub。** `.gitignore` 里已经排除了，
> 但你自己也要注意——密钥公开出去，几分钟内就会被盗刷。

### 3. 跑

```bash
# 先看看有没有麦克风
py 录音转文字.py --设备

# 说一句话，看能不能转成文字
py 录音转文字.py

# 让 agent 说一句话给你听
py 文字转语音.py "你好，我是你的语音助手"

# 走完整条链路（录音 → 识别 → AI 回答 → 合成 → 播放）

# 网页版（按住说话）
py 网页\后端.py
# 然后浏览器打开 http://127.0.0.1:8020
```

## 「换壳」是什么意思

客服的人设、知识库、兜底话术**全在 json 里**，不在代码里：

```json
{
  "名字": "示例中医诊所",
  "人设": "你是这家诊所的语音客服，说话温和、简短、口语化……",
  "知识库": [
    "门诊时间：周一至周六 上午 8:30-12:00，下午 14:00-18:00。",
    "挂号方式：现场直接挂号，也可以提前打电话预约。"
  ],
  "接不上时": "这个我不太确定，我帮您记下来，让医生回您电话，可以吗？"
}
```

```bash
py 客服大脑.py --租户 诊所 你们几点上班
#   → 我们周一至周六上午 8:30 到 12:00，下午 2 点到 6 点。周日全天休息。

py 客服大脑.py --租户 餐馆 牛肉面多少钱
#   → 牛肉面 22 一碗，咱家招牌，要来一碗不？
```

**代码一个字没改，只换了 json。**

## ⚠️ 踩过的坑（中文 Windows 专属，每个都花过时间）

| # | 现象 | 原因 |
|---|---|---|
| 1 | **录音全是静音，还不报错** | 联想等笔记本有**麦克风硬件静音键（F4）**，灯亮着时程序收到的是纯静音。先看那个灯。 |
| 2 | **脚本第一行就崩，`UnicodeEncodeError: 'gbk' codec`** | bash/cron 拉起 Python 时 Windows 用 GBK 编码，`print` 里带 emoji 就死。修：`sys.stdout.reconfigure(encoding="utf-8", errors="replace")` |
| 3 | **音量判断读出 0.0，其实是正常的** | `sf.read()` **默认读成 float64**，别拿它的 dtype 当"文件格式"。要看 `sf.info().subtype`。 |
| 4 | **第一句话总是白说** | 录音脚本要先**开录再倒数**。反过来（倒完才开始录）用户第一句就丢了。 |
| 5 | **`winsound` 播了但没声音** | 系统默认播放设备选错时，它**静默失败不报错**。改用 `sounddevice`，还能指定设备、能打印用的哪个。 |
| 6 | **curl 测接口报 `Invalid HTTP request`** | 中文直接塞 URL 没编码。用 Python 的 `requests(params=...)`，它自动编码。 |
| 7 | **能量式静音检测在噪音环境不可用** | 房间噪音峰值波动 10 倍时，判定线会被顶到说话声之上。**结论：改用"按住说话"，让用户控制起止。** |

---

## 一个诚实的结论

**"一直听着、自动响应"这个形态，用笔记本内置麦克风 + 普通房间噪音，做不稳。**

大厂做这个要专门的麦克风阵列 + 降噪算法。想做得稳，先解决硬件（贴嘴的麦克风 / 带麦耳机）。

**按住说话是可靠的** —— 什么时候开始、什么时候结束都由用户控制，不受噪音影响。先把这个用顺。
